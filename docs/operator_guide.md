# Operator guide

Start here. The other guides are in the same `docs` folder: [camera_placement.md](camera_placement.md), [calibration.md](calibration.md), [troubleshooting.md](troubleshooting.md), [camera_bracket.md](camera_bracket.md), and [clean_machine_test.md](clean_machine_test.md) (checklist for verifying a new PC).

## 1. Install on a fresh PC
The packaged app is self-contained: **no Python, Node.js or other runtime needs to be installed**, and no internet is needed. The needed Visual C++ runtime DLLs are inside the folder.
1. Unzip `HiveShotTracker_<version>_win64.zip` to a normal folder (for example `C:\HiveShotTracker`). Keep the whole folder together. `README.txt` and `docs\` are next to the exe.
2. Double-click `HiveShotTracker\HiveShotTracker.exe`. The exe is not code-signed, so Windows SmartScreen may say "Windows protected your PC": click **More info**, then **Run anyway**. A console window opens and stays open while the app runs. If Windows Firewall asks, allow **Private networks** (needed only for GoPro RTMP; see troubleshooting.md).
3. The packaged exe opens your browser at **http://127.0.0.1:8765** by itself a moment after it starts (start it with `--no-browser` to prevent that, or open the address by hand). The dashboard loads.
4. To use another port or data folder: `HiveShotTracker.exe --port 8766 --data-dir D:\hiveshot_data --autostart`.
5. **Stop the app by closing the console window** (this is the normal way to stop it; Ctrl+C in the console also works). When the app is stopped from outside, Windows reports an exit code of 0, 1 or 3 (3 is the usual one for Ctrl+Break or a window close). Any of these is normal and not an error.

**Data folder (default):** `%LOCALAPPDATA%\HiveShotTracker\data`, usually `C:\Users\<you>\AppData\Local\HiveShotTracker\data`. It is created on first start and is never inside the unzipped folder, so you can delete or replace the app folder without losing data.

Without a camera configured, the built-in demo footage can be used to see the dashboard working. Start `HiveShotTracker.exe --demo` (or click **Run demo** in the top bar; **Exit demo** returns to your own setup). Demo mode runs two bundled synthetic videos, starts no RTMP server, and keeps its data in a separate `demo` subfolder of the data folder, so real sessions are never touched. (Without `--demo`, `--autostart` or **Pipeline start** also runs the basic demo footage when no camera is configured.)

## 2. Camera setup
Place and aim the cameras exactly as in [camera_placement.md](camera_placement.md) (tape marks, lens heights, pitch, settings, pre-session checklist).
- **Option A, GoPro.** Either HDMI to a capture card (appears as a camera device; use its device index in Settings) or RTMP over Wi-Fi: in the GoPro Quik app choose Live Stream > RTMP and set the URL to `rtmp://<PC-IP>:1935/cam0` for camera A and `.../cam1` for camera B. The app starts its own RTMP server (included in the zip); the status page lists the exact URLs. HyperSmooth off, Linear lens, 1080p60.
- **Option B, USB global shutter.** Plug each camera into its own USB 3 port on the PC if you can (two 1080p90 streams can starve a single shared hub link; see troubleshooting.md, "Low fps"). Pick the device index in Settings (see `/api/devices`), 1920x1080, 90 fps, fixed exposure.

In the **Settings** tab, under **Sources**, each camera is a row with `cam_id`, `kind` (`file`, `device`, `rtmp` or `url`), `target`, `width`, `height`, `fps_hint`, `realtime` and `loop`. For a USB or capture-card camera set `kind` to `device` and `target` to the device index; the **detected devices** drop-down plus the row's **use picked device** button fills it in. For RTMP set `kind` to `rtmp`. Click **Save config**, then **Pipeline stop** and **Pipeline start** so the new sources take effect. **Add source** adds a row; **remove** deletes one.

## 3. Calibration
Full detail is in [calibration.md](calibration.md). On a fresh install the **Setup** tab opens by itself (the dashboard says "no calibration loaded" until you have done this); otherwise click the **Setup** tab. The wizard walks through six steps; every button named below is on that page.

1. **Cameras.** Plug in both cameras, press **Detect and preview**, then click **This is the -X wall camera** under the picture taken from the minus-X wall. That picture's camera becomes `cam0`, the other `cam1`. This replaces the configured sources.
2. **Lens (intrinsics), once per camera and lens setting.** Required until the camera's lens is measured: the app starts with a generic default lens, warns "camera X uses default lens intrinsics ... run the Lens step", and the wizard will not finish while it does. Press **Open printable checkerboard (PDF)**, print it at 100 % scale (1.00 in squares) on a flat, stiff board. For each camera press **Start recording**, hold the board 1.5 to 3 ft from the camera and tilt it around (left, right, up, down, the corners of the picture) for about 20 s, then **Stop recording**. Green is under 1 px, amber (1 to 2 px) is accepted with a warning that stays on the dashboard, red (over 2 px) is saved as a poor lens and the wizard will not finish until you redo it closer to the camera (1.5 to 3 ft). (The same recording is also on the **Calibration** tab: **Start intrinsics** / **Stop intrinsics** on each camera card.)
3. **Tags and auto-calibration (the normal way for extrinsics, both cameras at once).** First **tip both HIVEs by hand so that both audience CELLs are up** (the red one is at match start; the blue one starts with its far CELL up). The calibration uses that arrangement for the tags of both HIVEs whatever the HIVE state in the top bar says; the Setup page warns "Tip both HIVEs so both audience CELLs are up before calibrating" when the tags it sees say otherwise. Press **Open printable tag sheet (PDF)** (`/api/calib/tags.pdf`) and print it at 100 % scale: four letter-size pages, one AprilTag per page, each **6.00 in** square (check the printed line with a ruler). Cut each tag out on its dashed line (that leaves a 0.5 in white border, which the camera needs), glue it flat on stiff card (foam core), and put it where [calibration.md](calibration.md) section 3A shows (each page names its position). Tags 100 and 101 lie flat on the slanted logo panel of the HIVE frame. Tags 102 and 103 stand on the tiles at the audience-side base corners leaning back 20 degrees: build each stand from a foam-core wedge **4 in wide, 2 in deep along the floor and 5.5 in tall** (a right triangle, 2 / 5.5 = tan 20 degrees), glue the back of the card to the sloped face with the card's bottom edge at the low end, and rest it on the foot bar end; measure the card's position with a tape to 0.25 in. With the tags in view of both cameras press **Auto-calibrate**. The tags can stay taped between sessions; after every tripod move press **Auto-calibrate** again (or **Auto-calibrate all** on the **Calibration** tab). No printer: choose "No printer: use the HIVE's own tags"; it is less accurate.
   - **Reading the result.** *Reprojection px* should be under 2. *Fit residual* (in) is how well the tag corners fit the solved pose; it is **not** the pose error (the API field is `fit_residual_in`). *Out-of-sample error* (also *Max error* in the cross-check) is the number that counts: it triangulates tags that the solve did **not** use (the field's own HIVE tags after a kit solve, or the kit tags after a HIVE-only solve) and compares them with their known positions. Keep it **within 1 in**.
   - **What gets refused.** The app will not save a solve whose reprojection error is over 4 px, whose camera delivers a different picture size than the one the lens was measured at, or whose held-out tags are more than 2 in off (also against the other camera's pose). It tells you which and keeps the previous calibration.
   - **Both cameras moved?** On the **Calibration** tab press **Recalibrate both** (same as **Auto-calibrate all**): it drops both old poses, solves both, checks the new pair, and puts the old ones back if anything fails. Pressing **Auto-calibrate** on one camera alone checks it against the other camera's *old* pose and is refused when that one also moved. If only one camera really moved and the check still fails, **Force this camera only** saves it anyway; the other camera then shows **pair stale: recalibrate both** and the wizard will not finish until you press **Recalibrate both**. **Reset calibration** (asks first) removes the saved camera poses of all cameras so you can start over; it **keeps the lens calibration**, so you do not have to redo the checkerboard step.
   - If the answer says "in-sample" / `out_of_sample: false`, no spare tag was in view, so the number only re-measures the tags the solve used: make a HIVE tag or an unused kit tag visible to both cameras and press **Cross-check** on the **Calibration** tab.
4. **Verify HIVE tags (optional).** Make sure the audience CELL is up, press **Learn**. Tags of the far CELL face away from cameras on the audience side: if the far-up state shows "not visible from these cameras" that is expected; the step is complete once the audience state is learned.
5. **Ball colors.** Place a ball in view, choose its type, click the ball in the picture. **Undo last sample** and **Reset to defaults** undo a wrong click.
6. **Done.** **Start pipeline and session** first checks the calibration: it refuses (and tells you why) while a camera has default or poor lens intrinsics, a camera delivers a different picture size than its lens was measured at, a camera shows *pair stale*, or the cross-check error is over 1 in. It warns when a camera's pose came from fewer than 3 tags (a third tag makes it much less sensitive to a mis-taped one). When a camera's cross-check is only in-sample (no spare tag in its view), the check still passes but the page shows a warning for that camera: tape errors, a resolution mismatch or a camera swap would not be detected, so verify by clicking the 8 corners (the click method below).

**Fallback: click the points by hand** (when a tag cannot be taped on, is hidden, or Auto-calibrate reports an error you cannot fix). On the **Calibration** tab each camera card has **Refresh image**, **Undo point**, **Clear** and **Solve extrinsics**: click the listed field points on the image in the order shown on the right, then **Solve extrinsics**; the result line shows the error. Clicked points are accurate to about 1.5 px, so this is looser than the kit; the same save checks apply.

The **Current calibration** box at the bottom of the **Calibration** tab shows what is saved; keep a copy of `calibration.json` after each good calibration. Budget under 10 minutes for a full re-calibration. A **calibration mismatch (n)** tag at the top means a camera is delivering a different image size than the one it was calibrated at (for example calibrated at 1920x1080, now sending 1280x720); hover over it for details, then fix the camera resolution or redo the lens step.

**Field size.** `field_size_in` (inside wall to inside wall; measure wall to wall with a tape; default 144 in) sets the field box in the 3D viewer and the geometry the API serves; it does not move the cameras. Change it through the config (`PUT /api/config`, see api.md).

## 4. Practice session, step by step
1. Open the dashboard and click **Pipeline start** (top bar). The **Cameras** panel on the left should show a live preview and the fps for each camera, and the tag at the top reads `pipeline: running`.
2. Set **Alliance** and **Up cell** (`audience` or `far`) to match the real HIVE, then click **Set HIVE state**. Update it whenever the HIVE tips.
3. Type a name in the session box and click **Start session**. (If you shoot without a session, shots are stored under "unassigned".)
4. Shoot. Each shot appears in the **Shots** tab a moment after the ball settles (about 0.75 s). Balls fired within 1.5 s of each other count as one burst.
5. Watch the counters on the **Dashboard** tab: Shots, Made, Bounce-out, Miss, Make rate, Tips, and the mean exit speed and launch angle.
6. Click **End session** when done. Past sessions stay available in the **Session** drop-down after a restart.

## 5. Reading the dashboard
- **Made**: the ball entered the up CELL opening and stayed in.
- **Bounce-out**: entered the opening, then left it. Not counted as made, but tracked separately because it points to exit speed or angle rather than aim.
- **Miss**: never entered the opening.
- **Failures by burst order** (chart): shots within the burst gap are numbered 1, 2, 3... in firing order, and the chart counts non-made shots at each position ("burst 1" = first ball, ..., "burst >4"). Red bars are all failures, amber bars are bounce-outs. A tall bar at 4 or more usually means the robot slows or jams late in a burst.
- **By ball type**: pollen versus nectar breakdown (table next to the chart).
- **Tip events**: collapsible list under the chart of HIVE tips and which shot caused them.
- **Shots tab** columns: `#`, Time, Burst (burst number and position in the burst), Ball, Result, **Exit m/s**, **Exit in/s**, **Angle** (launch elevation above horizontal, degrees), **Azimuth** (heading relative to the field axes, degrees), **Apex in** (highest point of the flight, inches above the floor). Use the **Result** filter (all, made, miss, bounce_out) to narrow the list. Exit speed is the ball speed leaving the robot, from the fitted 3D track; it is best with the optional exit-speed camera C or 120+ fps.
- **Equation and fit RMSE**: shown in the **Replay** tab's info box for the selected shot. The equation looks like `z = a s^2 + b s + c (in)`, the fitted height z against distance s along the shot plane. A large fit RMSE means a poor track; treat that shot's numbers with caution.

## 6. Replay
Click a row in the **Shots** tab; the **Replay** tab opens with the shot. The 3D viewer shows field, HIVE, robot and ball path (solid yellow is the measured track, dashed cyan the fitted parabola). Controls: **Play** (becomes **Pause**), the slider to scrub, the **Speed** drop-down (0.1, 0.25, 0.5, 1 x), and a **Follow ball** checkbox; drag to orbit, wheel to zoom. Shots with a saved clip show a **clip** link to the camera video.

## 7. Export
Select a session in the **Session** drop-down, then click **Export CSV** in the top bar, or open `http://127.0.0.1:8765/api/sessions/<id>/export.csv`. One row per shot with result, exit speed, angles, apex and equation. Opens in Excel.

## 8. Data location and backups
Everything lives in the data folder. By default that is `%LOCALAPPDATA%\HiveShotTracker\data` (see section 1); `--data-dir` overrides it (recommended if several people share the PC or you want it on another drive).
- `hiveshot.db`: sessions and shots
- `config.json`: settings (the **Settings** tab writes here); `calibration.json`: camera calibration
- `clips\`: saved shot video

Back up by closing the app and copying the whole data folder. Restore by copying it back. Copy `calibration.json` after every good calibration; it is the hardest thing to recreate. Uninstalling is just deleting the unzipped folder; delete the data folder too only if you want to discard your data.
