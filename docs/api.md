# HiveShotTracker HTTP/WebSocket API contract (v1)

Owned by the lead. Backend (hiveshot/app.py) and UI (ui/) both implement this exactly. Changes go through the lead.

Server: FastAPI on http://127.0.0.1:8765. Static UI served at `/` from `ui/`. All JSON. Units: inches, seconds, degrees, inches/second unless a key says otherwise (`*_mps` = m/s).

## Sessions
- `GET /api/sessions` → `[{session_id, name, started_at, ended_at|null, shots, made}]`
  - On server startup, sessions left open (`ended_at` null) by a previous run are ended (`ended_at` = now) before autostart creates a new one.
- `POST /api/sessions` body `{name}` → `{session_id}` (starts a new session and makes it current; ends any running one)
- `POST /api/sessions/{id}/end` → `{ok: true}`
- `GET /api/sessions/{id}/stats` → SessionStats as dict (see hiveshot/models.py SessionStats; `failure_order_hist` and `bounce_out_order_hist` keys are strings "1".."5")
- `GET /api/sessions/{id}/shots` → `[ShotSummary]` where ShotSummary = `{shot_id, t_launch, burst_id, burst_index, ball_type, result, exit_speed_ips, exit_speed_mps, launch_angle_deg, launch_azimuth_deg, apex_z_in, equation, clip_url|null}`
  - Classification: a track is `bounce_out` only when the ball leaves through the opening (an outward crossing of the opening plane inside the opening polygon); leaving the CELL box through any other face is `made` if it stayed inside for `settle_time_s`, else `unknown` with the note "track left the CELL through a wall (synthetic?)". A track that starts mid-flight is classified normally (its exit speed is measured from its first visible point).
- `GET /api/sessions/{id}/export.csv` → CSV download (stats.shots_to_csv)
  - CSV adds a `t_launch_wall` column (ISO 8601, blank when unknown); text cells starting with `=`, `+`, `-`, `@` are prefixed with a single quote to neutralize spreadsheet formulas.
- `GET /api/shots/{shot_id}` → full shot: ShotSummary plus `track: [{t,x,y,z}]`, `parabola: {a,b,c,rmse_in}`, `drag: {v0:[..], p0:[..], k_per_in, rmse_in}|null`, `launch_point:[x,y,z]|null`
- `GET /api/sessions/{id}/tips` → `[{t, alliance, new_up_cell, caused_by_shot_id}]`
  - ShotSummary additive fields: `dropped_during_flight` (int): frames the cameras dropped during the shot's flight (0 = none; also noted in the shot notes as "frames dropped during flight (N)"); `t_launch_wall` (string|null): ISO 8601 wall-clock launch time = session `started_at` + `t_launch`, null when the session start is unknown. A shot whose track ends mid-air or near the opening without evidence of a miss has `result: "unknown"` (notes: "track lost mid-air" / "track lost near the opening"), not `miss`.

## Cameras and pipeline
- `GET /api/config` → current config dict (sources, calibration file path, alliance, hive state, robot box dims, burst gap, thresholds)
- `PUT /api/config` body: partial config dict → full config after merge. Persisted to data/config.json. While the pipeline runs, a change to `sources` is rejected with 409; `burst_gap_s`, `settle_time_s`, `finalize_delay_s`, `stitch_gap_s`, `robot`, `preview_fps` and the HIVE state apply immediately, `detector` and `calibration_path` at the next start.
  - Validation (422, nothing applied or saved): every source `kind` must be `file|device|rtmp|url`, `cam_id`s must be non-empty and unique, `target` must be non-empty. For `kind: "rtmp"` a bare stream name such as `cam0` is accepted and resolved at start to `rtmp://127.0.0.1:1935/<name>`; a full URL is used as given.
  - `detector.motion_scale` (float in (0, 1], default 0.5): the motion (background-subtraction) model runs on the processed frame scaled by this factor, which halves the detector cost; 1.0 restores full-resolution motion. Applies at the next start.
- `GET /api/devices` → `[{index, width, height, fps}]` (ingest.list_devices)
- `POST /api/pipeline/start` → `{ok, running: true}`; `POST /api/pipeline/stop` → `{ok, running: false}`
- `GET /api/pipeline/status` → `{running, cameras: {cam_id: {fps, dropped, frames_read, is_alive, last_error, reconnects, props}}, detector_fps, last_shot_id, hive_state: {alliance, up_cell}, rtmp: {available, running, urls: {cam_id: url}}}`
  - `calibration_loaded` (bool, additive): true when intrinsics and extrinsics are loaded for both cameras. `warnings` (list of strings, additive): why the pipeline may produce no or poor shots, e.g. `no calibration loaded: 3D reconstruction disabled`, `camera cam1 resolution mismatch (1280x720 vs 1920x1080)`, `single-camera mode: ...`, stale extrinsics, per-camera errors, `camera cam0 dropped N frames (processing too slow)`.
  - `timing` (object, additive): moving averages of per-frame CPU stage times in ms, mean over cameras: `{detect_ms, track_ms, preview_ms, ring_ms, recon_ms}` (`recon_ms` is per reconstruction cycle); `timing_per_camera` has the same per-frame keys for each camera.
  - `timing` also carries `offset_s` (camera B -> camera A clock offset in use, null before the first estimate) and `offset_confidence` (0..1, the estimator's peak-versus-runner-up margin). The offset search is limited to +-0.1 s when both sources are devices on this PC, +-2 s for rtmp/url sources, +-0.5 s otherwise; an ambiguous estimate (confidence < 0.3) is revisited every 3 s instead of every 30 s.
  - `warnings` also reports ball tracks that found no partner in the other camera ("N ball track(s) could not be paired between the cameras and were dropped: shots may be missing").
  - `session_id` (string|null, additive): the session new shots are stored in; null after a session was ended (shots then go to the session `unassigned`). `calibration_mismatch` (object, additive): `{cam_id: "1920x1080 vs 1280x720"}` (calibration size vs delivered frame size), empty when consistent.
  - `cameras[cam_id].ended` (bool, additive): true when a file source reached end-of-file cleanly; such a camera reports `is_alive: false`.
- `GET /api/preview/{cam_id}.mjpg` → multipart/x-mixed-replace MJPEG stream of the latest frame with detections drawn (max 15 fps, 960 px wide); the JPEG is only encoded while at least one client is attached
- `GET /api/preview/{cam_id}.jpg` → single JPEG of the latest frame (for the calibration click UI)
- `POST /api/hive/state` body `{alliance, up_cell}` → sets the HIVE state manually (used until AprilTag detection is proven)

## Calibration
- `POST /api/calib/intrinsics/{cam_id}/start` and `/stop` → records frames for N seconds; `/stop` returns `{reprojection_rmse_px, frames_used}` and saves
- `POST /api/calib/extrinsics/{cam_id}` body `{points: [{u, v, name}]}` where name matches docs field point sheet → `{rmse_in, per_point: [{name, err_px}]}`
- `GET /api/calib` → current calibration JSON (calib.save_calibration format) Each extrinsics entry carries `stale` (bool, additive): true when new intrinsics were saved after the extrinsics were solved; re-solve them.
- `GET /api/calib/checkerboard.pdf` → the printable 10x7-square (9x6 inner corners), 1 in checkerboard as `application/pdf`, attachment filename `checkerboard_10x7_1in.pdf` (generated once into the data dir, then cached)
- `GET /api/calib/points` → `[{name, xyz: [x, y, z]}]` the ordered field reference points (click order, inches, field frame) accepted by `POST /api/calib/extrinsics/{cam_id}`
- `POST /api/calib/crosscheck` (body optional `{"in_sample": true}`) → `{points: [{name, kind, xyz_measured: [x,y,z], xyz_expected: [x,y,z], error_in, residual_in}], max_error_in, within_1_in, out_of_sample, held_out, warning?}`. **Out-of-sample by default**: it detects the AprilTags in the latest frame of both cameras and triangulates the corners of tags that *no* extrinsics solve used, comparing each with its known field position (`kind` `"hive"`: the computed CAD corners of both alliances' HIVE tags in the calibration state (see "Calibration state" below), name `hive tag 34 corner 0`; `kind` `"kit"`: the printed kit tags, name `tag 100 corner 0`). Which tags a solve used is recorded per camera (`solve_tags` in the calibration JSON): after a kit solve the HIVE tags are held out; after a HIVE-tags-only solve (`source: "hive"`) the kit tags are held out; after a click solve every visible tag is held out; a tag used by either camera's solve is never held out. `held_out` says which kinds were checked (`"HIVE tags"`, `"kit tags"`, `"HIVE tags and kit tags"`). `within_1_in` is `max_error_in <= 1.0`. When nothing can be held out (pipeline not running, no unused tag visible in both cameras, or the solves are not recorded) it falls back to the **in-sample** re-measurement of the points the solves were made from (stored per camera in the calibration JSON under `clicks`, `{cam_id: [{name, u, v}]}`) and says so: `out_of_sample: false` plus a `warning`. `{"in_sample": true}` asks for that re-measurement directly. 409 when either camera lacks calibration, or nothing is held out and no stored clicks exist; 422 when no point is visible in both cameras.
- `GET /api/field/geometry` → field.to_json() (HIVE wireframe, cell polygons for both states, field bounds) for the 3D viewer

## WebSocket
- `WS /ws` → server pushes JSON messages:
  - `{"type":"status", ...status dict as above}` every 1 s
  - `{"type":"shot", "shot": ShotSummary}` when a shot is finalized
  - `{"type":"tip", "tip": {...}}`
  - `{"type":"shot_updated", "shot": ShotSummary}` (additive) when a later shot changes an already-announced shot (burst re-assignment: `burst_id`, `burst_index`)
  - `{"type":"stats", "stats": SessionStats dict}` after each shot

## Static
- `/` → ui/index.html; `/vendor/*` → ui/vendor; `/clips/{file}` → data/clips

## Config dict shape
```json
{
  "sources": [{"cam_id":"cam0","kind":"file|device|rtmp|url","target":"...","width":1920,"height":1080,"fps_hint":60,"backend":"auto","loop":true,"realtime":true}],
  "calibration_path": "data/calibration.json",
  "alliance": "red",
  "hive_up_cell": "audience",
  "robot": {"length":18,"width":18,"height":18,"launch_exit_height":12},
  "burst_gap_s": 1.5,
  "settle_time_s": 0.75,
  "detector": {"min_radius_px":4,"max_radius_px":60,"pollen_hsv":[[..],[..]],"nectar_hsv":[[..],[..]],"motion_thresh":25},
  "preview_fps": 15,
  "stitch_gap_s": 2.0,
  "finalize_delay_s": 0.5,
  "field_size_in": 144.0
}
```

`field_size_in` (default 144.0, 60 to 400): the real field size, **inside wall to inside wall; measure wall to wall with a tape**. `GET /api/field/geometry` returns `field_size` and `bounds` for this size (`bounds.min/max` x and y are +-`field_size_in`/2) and the 3D viewer draws its floor from it. It does not move the cameras or the HIVE.

## Setup, auto-calibration and tuning (v1.1, 2026-10-10)

- `GET /api/setup/status` → `{cameras_detected: [{index,width,height,fps}], sources_configured: bool, calibration_loaded: bool, tags_seen: {cam_id: [tag_id,...]}, pipeline_running: bool, recommendations: [str]}` — the wizard polls this.
  - Implementation notes (additive): `tags_roll` `{cam_id: {cluster: {roll_deg, sign}}}` for the HIVE tag clusters in view (`sign` +1 = right side up = up CELL, -1 = flipped = down CELL; from the tag's field-frame up vector when the camera is calibrated, else from its in-image roll). `cameras_detected` is always filled: devices the running pipeline holds are reported from its own stream properties, every other index (0-5) is probed through `ingest.list_devices` (cached 30 s; indexes the pipeline has open are never probed), whatever the pipeline is doing. Recommendations are generated from the actual state (not in demo mode): no device detected ("plug in the cameras"), only video-file sources ("The sources are video files; use the Cameras step to pick real cameras."), a camera that dropped frames in the last minute ("camera X is dropping frames (N in the last minute): processing too slow; close other programs or lower the preview fps."), one source only, `camera X is at N fps; move it to its own USB port, not a shared hub.` (running device camera at >= 1080p below 59 fps), no calibration ("print the tag sheet ... Auto-calibrate"), tags seen per camera while uncalibrated.
- `GET /api/calib/tags.pdf` → printable letter-size kit, one page per AprilTag 36h11 tag (4 pages, ids 100–103, 6.0 in square, labeled with their place: 100/101 on the slanted logo panel, 102/103 standing at the audience-side base corners; see docs/calibration.md) plus a size check line; print at 100 % scale. Tag ids and sizes: `GET /api/calib/tags` → `[{id, size_in, name, xyz_center, corners_xyz}]`.
- `POST /api/calib/extrinsics/{cam_id}/auto` → detects the kit tags (and HIVE tags if `hive_tags: true` in the body and their layout is verified) in the latest frame, solves the pose, saves it, returns `{rmse_in, tags_used: [id], reprojection_px}`; 422 with a plain-language reason if fewer than 2 tags are visible.
  - Body `{source: "kit"|"hive"|"both"}` (default `both`; legacy `use_hive_tags: true` means `hive`): `kit` = the printed kit tags (ids 100-103), `hive` = the field's own HIVE tags at their computed (CAD) positions for the current HIVE state (learned tags only fill ids without a computed position), `both` = every detected tag with a known pose. Response `{rmse_in, tags_used, tags_missing, reprojection_px, max_corner_px, hive_tags_used, source, warnings}`; `warnings` holds "calibrated from HIVE tags only: expect 2-3x lower accuracy than the kit" when no kit tag was used. The kit corner pixels are stored as `clicks` ("tag 100 corner 0") so `POST /api/calib/crosscheck` works after auto-calibration.
- `POST /api/calib/auto_all` → runs auto extrinsics for every running camera, then crosscheck; returns per-camera results and `max_error_in`.
  - Without a `source` in the body each camera is solved from the **kit** first (so the HIVE tags stay out of the solve and the crosscheck can hold them out); a camera that cannot read two kit tags falls back to the HIVE tags (the crosscheck then holds out the kit tags). A `source` (or `use_hive_tags`) in the body is used for every camera as given.
  - Response `{ok, results: {cam_id: {ok, ...auto response | status, error}}, crosscheck: {...}|null, max_error_in}`; 409 when the pipeline is not running.
- `POST /api/detector/sample` body `{cam_id, u, v, ball_type}` → samples a 9x9 HSV patch around the click on the latest full-res frame, widens the current range for that ball type to include it (with margins), persists it in config, returns the new range.
  - Response `{ball_type: "pollen"|"nectar", sampled_hsv: [h,s,v] (median of the 9x9 patch), range: [[lo],[hi]]}`. The range only ever widens: lo = min(old lo, sample - [8,40,40]), hi = max(old hi, sample + [8,40,40]), clamped to H 0-179, S/V 0-255. Persisted to `config.detector` and applied to the running detectors at once. 409 before frames exist, 422 for an unknown ball type or a click outside the frame.
- Config additions (defaults): `session_name_template: "Practice {date} {time}"`, `session_idle_end_min: 10`, `autosave_csv: true`, `profiles: {"arducam_1080p90": {...}}`, `default_intrinsics: {"arducam_2.3mp_110": {...}}` applied when a camera has no calibration (status.warnings says so).
  - Details: `profiles` values are config patches (`{"sources": [...]}`) to apply with `PUT /api/config`; `default_intrinsics` uses the first entry for any camera that has no intrinsics (`status.warnings`: "camera X uses default lens intrinsics (fx 771): run the Lens step"; see "Calibration provenance" below); `session_idle_end_min` 0 turns the idle end off; when a session ends idle the pipeline emits `{"type":"session_ended","session_id","reason":"idle","csv":path|null}`, writes `data/exports/<session name>_<session id>.csv` (if `autosave_csv` and the session has shots), and the next shot opens a new session named from `session_name_template` (a session ended by the user is NOT restarted: shots go to `unassigned`). `hive_tags_verified` (default false) enables inferring the up CELL from which CELL tag ids are visible while the cameras are not calibrated.
- Status additions: `hive_state_source: "manual"|"tags"`; when tags are visible on the up CELL the pipeline sets the HIVE state itself and logs tips.
  - `hive_state_source` is "tags" once the tags have decided (or both HIVE states were learned) and the user has not set the state manually since; `POST /api/hive/state` switches it back to "manual" until the next tag-confirmed state. The pipeline infers the state from the tags at ~2 Hz per camera (`tagkit.infer_hive_state`; computed up-CELL geometry as soon as the cameras are calibrated, learned tables once both states are learned) and commits a change after 3 agreeing samples spanning at least 250 ms, logging a tip.

## HIVE tag learning (v1.2, 2026-10-10)
- `POST /api/calib/hive_tags/learn` body `{state: {alliance, up_cell}}` → with both cameras calibrated, detects ids 30–45 in both latest frames, triangulates every tag corner seen in both, stores `hive_tags[state_key][id] = corners_xyz` in the calibration JSON; returns `{learned_ids, missing_ids, max_residual_in, visible_per_camera}`; 422 if fewer than 2 tags are seen in both cameras.
  - Response adds `up_cell_error_in` (additive): mean distance between the triangulated up-CELL tag corners of that state and the computed (CAD) ones, a sanity check of the whole calibration (null when the up CELL's tags were not seen by both cameras). `GET /api/calib/hive_tags` → `{alliance, states: {state_key: {tags: {id: {corners_xyz, center_xyz}}, row_height_in: {cluster: z}}}, ready, hive_state_source}`.
- `GET /api/calib/hive_tags` → the learned table per state plus `row_height_in` per cluster.
- Status: `hive_state_source` becomes "tags" automatically once both states are learned; `tags_seen` lists ids per camera. Tip events are then generated by the pipeline from state changes with 3-frame/250 ms hysteresis.
- HIVE-tag calibration and state inference work per camera: a camera that cannot read the HIVE tags is refused (`POST /api/calib/extrinsics/{cam_id}/auto` with `source: "hive"` → 422 "no HIVE tags visible to {cam}..."; `auto_all` reports it per camera with `ok: false`), and `hive_state_source` becomes "tags" as soon as at least one calibrated camera sees a cluster (right side up = up CELL) with the 3-sample/250 ms hysteresis. Only `hive_tags/learn` needs both cameras to see the tags.
- `POST /api/calib/extrinsics/{cam_id}/auto` body may include `{use_hive_tags: true}` to solve from learned HIVE tags for the current state (kit-free recalibration).

## Demo mode (v1.3, 2026-10-10, owner request)
- Runs with nothing external: two bundled synthetic videos (fixtures/synth_20 if present, else fixtures/synth_basic), realtime pacing, loop on, the calibration embedded in the fixture truth JSON, HIVE state manual (audience up), no RTMP server started, wizard suppressed.
- `python -m hiveshot.app --demo` (also the packaged exe `HiveShotTracker.exe --demo`): applies the demo config to a separate data dir `<data>/demo` (so real data is never touched), starts the pipeline, creates a session named "Demo {date} {time}", opens the browser.
- `POST /api/demo/start` → same from a running app: stops the pipeline, swaps to the demo config (in-memory, not persisted to config.json), starts, creates the demo session; returns `{ok, session_id}`. `POST /api/demo/stop` → stops the pipeline and restores the saved user config; returns `{ok}`.
- Status gains `demo: bool`. The UI shows a "DEMO" badge and a "Run demo" / "Exit demo" button in the top bar; while in demo the Setup wizard does not auto-open and the Settings tab shows a banner "demo config (not saved)".

## Calibration provenance, lens gate and save gates (v1.4, 2026-10-10)

- **Provenance in status.** `GET /api/pipeline/status` (and the WebSocket status) gets, per camera and overall, `calibration_source` and, per camera, `intrinsics_source`; overall also `intrinsics_default` (any camera still on the generic lens).
  - `cameras[cam].calibration_source`: `"none"` (no extrinsics, no lens), `"default_intrinsics"` (no extrinsics, generic default lens only), `"fixture"` (calibration embedded next to a bundled fixture video), `"click"`, `"hive"` or `"kit"` (how the saved extrinsics were solved: field points clicked by hand, HIVE tags only, or at least one kit tag). The top-level `calibration_source` is the least trustworthy of the cameras (order none < default_intrinsics < fixture < click < hive < kit). `GET /api/setup/status` repeats `calibration_source` and `intrinsics_default`.
  - `cameras[cam].intrinsics_source`: `"measured"` (checkerboard, or a calibration file without the key), `"profile"` (the measured `intrinsics` slot of `config.active_profile`) or `"default"` (generic `default_intrinsics`). Stored in `calibration.json` as `intrinsics_source` {cam: source}; the extrinsics solves as `solve_tags` {cam: {source, tags_used}}.
  - **Fixture calibration is a convenience, not a calibration.** The `*_truth.json` next to a fixture video is read only in demo mode or when every configured source is a bundled fixture file (`fixtures/...`). Even then `calibration_loaded` is `false` outside the demo (the cameras can reconstruct, but nothing was calibrated), so a fresh install opens the setup wizard. With any device/rtmp/url source and no calibration file there is no extrinsics at all and `calibration_loaded` is `false`; the warning "no calibration loaded: 3D reconstruction disabled" stays until a real calibration exists.
- **Lens gate.** While a camera's `intrinsics_source` is `"default"` the status warning `camera X uses default lens intrinsics (fx 771): run the Lens step` stays, also after extrinsics are saved (the default source is written to `calibration.json` and survives reloads until `POST /api/calib/intrinsics/{cam}/stop` stores measured intrinsics). Extrinsics results (`POST /api/calib/extrinsics/{cam}`, `.../auto`, and each camera in `auto_all`) carry `intrinsics_default: true` in that case, plus a warning string.
  - `config.profiles[name].intrinsics` (optional object `{width, height, fx, fy, cx, cy, dist}`) is the slot for lens intrinsics measured on a real camera model; `config.active_profile` (default `null`) names the profile whose slot is used for every camera that has no measured intrinsics of its own (`intrinsics_source: "profile"`, no warning).
- **Save gates.** `POST /api/calib/extrinsics/{cam}` and `.../auto` refuse to save with **HTTP 409**, keep the previous calibration, and return the reason in `detail` plus the numbers in the body (`refused: true`, `cam_id`, `reprojection_px`, `frame_size`, `intrinsics_size`, `oos_error_in`, `crosscheck_error_in` where known) when: reprojection RMSE is over 4 px; the camera frame size differs from its intrinsics' size; a tag corner that the solve did not use is more than 2 in from its known position (`oos_error_in`: the distance from the known 3D corner to the camera ray through the detected pixel, max over held-out corners), or, when the other camera is calibrated, the pair's out-of-sample cross-check would exceed 2 in (`crosscheck_error_in`). In `auto_all` a refusal appears as `results[cam] = {ok: false, status: 409, refused: true, error, ...numbers}`.
- **Result fields.** Auto and click solves return `fit_residual_in` (the fit RMSE of the tag corners or clicked points in inches; this is what the wizard used to call "Pose error" and is **not** a pose error; `rmse_in` is kept as an alias) and `oos_error_in` (above; `null` when no held-out tag is visible, always `null` for the first camera of a pair that sees no spare tag). Click solves also return `reprojection_px` (RMS of the clicked points).
- **Learn.** `POST /api/calib/hive_tags/learn` returns `learned: bool`, `complete: bool` (the `<alliance>_audience` state is stored) and, when **no** HIVE tag is visible to either camera (the far CELL's tags when it is up, seen from the audience side), HTTP 200 with `learned: false`, `learned_ids: []`, `missing_ids`, `reason` ("... not visible from these cameras ...") instead of an error, so the wizard step can finish. One or more tags visible but fewer than two common to both cameras is still 422.
- **Done gate.** `POST /api/setup/finish` runs the cross-check and returns `{ok: true, max_error_in, out_of_sample, calibration_source}` (200), or HTTP 409 `{detail, refused: true, max_error_in?, intrinsics_default_cameras, ...}` when any camera has `intrinsics_source: "default"`, the cross-check cannot run, or its `max_error_in` is over 1 in. In demo mode it returns `{ok: true, demo: true}` without checking. The wizard's Done step calls it before starting the session.

## Calibration state (v1.5, 2026-10-10)

Calibration needs a known HIVE arrangement, `field.CALIBRATION_STATE`: **both audience CELLs up** (`{red: audience, blue: audience}`). The match-start state (`field.MATCH_START_STATE`, red audience up and blue far up) and the pipeline's current HIVE state (`POST /api/hive/state`) are for shot classification only and have no effect on calibration.
- `GET /api/calib` and `GET /api/setup/status` return `calibration_state` (`{"red": "audience", "blue": "audience"}`).
- `POST /api/calib/extrinsics/{cam}/auto` (sources `hive` and `both`), the held-out tags of `POST /api/calib/crosscheck` / the save gates / `auto_all`, and `POST /api/setup/finish` use the computed positions of **both alliances'** HIVE tags in that state (`tagkit.hive_tag_defs` per alliance, ids 30-45 as visible), regardless of the current alliance or HIVE state; positions learned for a calibration-state key (`red_audience`, `blue_audience`) override the computed ones. The Done gate does not look at the match-start state.
- `POST /api/calib/hive_tags/learn` without a `state` learns the calibration state for each alliance (each restricted to its own ids) and returns the usual fields aggregated plus `states: {key: single-state result}` and `errors: {key: reason}` for an alliance whose tags are seen by fewer than two common cameras; an alliance with no visible tag is reported with `learned: false`. `complete` is `true` once any `<alliance>_audience` state is stored. With a `state` in the body behaviour is unchanged.
- **Advice.** While the pipeline runs, `recommendations` of `GET /api/setup/status` gets "Tip both HIVEs so both audience CELLs are up before calibrating (<why>)." when the scanned tags suggest another arrangement: an alliance's audience cluster reads upside down (`tags_roll` sign -1), its far cluster reads upright, or no tag of one alliance's audience CELL is visible while the other alliance's are.

## Pipeline hardening (v1.6, 2026-10-10)

- **Per-frame errors.** An exception in a per-frame step (detection, 2D tracking, clip ring / preview; seen: `Unknown C++ exception from OpenCV` in `cv2.resize` under CPU saturation) no longer kills the camera loop: the frame is skipped (detection errors count as an empty frame so tracks age normally), the first error of each kind per camera is logged once with a traceback, the rest at debug level. `GET /api/pipeline/status` gets `cameras[cam].errors` (count) and `cameras[cam].loop_restarts`, and `warnings` gets `camera X: N frame processing error(s), last: <stage>: <message>`.
- **Loop restart.** If a camera loop dies from an unexpected exception it is restarted (at most 3 times per minute, `camera X: processing loop restarted N time(s) after an error`); a loop that keeps failing is stopped, the camera is marked done and `warnings` says `camera X: processing loop failed ... and was stopped`.
- **Watchdog.** A health check every 2 s. If a camera's frames keep arriving but its detector has not run for more than 3 s, or tracks are pending and no reconstruction cycle completed for more than 10 s, `warnings` gets `pipeline stalled: detector <cam>` / `pipeline stalled: reconstruction` (kept until the run is stopped) and the component's thread is replaced by a fresh one (the stuck one is retired by a generation number).
- **"N ball track(s) could not be paired".** Emitted only for a 2D track with at least 3 detections over at least 0.3 s that found no partner **and** that no reconstructed shot covers in time (cam B shifted by the time offset, +-0.1 s); a leftover fragment of an already reconstructed flight, a short track, or a track overlapping a shot is a debug log line, not a warning.
- **Fast low-arc shots.** The ballistic extension that completes a shot whose last measured point is within 6 in of the opening plane now steps at most 1.5 in along the path (it was a whole 1/60 s frame, 8 in at 500 in/s, which put the appended point outside the 12 in deep CELL's profile and read as "left through a wall" = `unknown`). Verified up to 590 in/s at 60 fps (flat 45 degree launches, 7 to 9 frames in flight): regression fixture `fixtures/synth_lowarc` (6 shots, 480 to 600 in/s, 2 deliberate misses), generated with `python -m hiveshot.synth --out fixtures/synth_lowarc --shots 6 --spacing 0.4 --fps 60 --seed 4242 --width 1280 --height 720 --speed-range 480,600 --arc low`. `synth` gained `--speed-range LO,HI` (default 220,340) and `--arc high|low` (default high; `low` = launch elevation 20 to 50 degrees, no apex limit).

## Pair gate, reset, lens quality, finish warnings (v1.7, 2026-10-10)

- **`POST /api/calib/auto_all`** (body optional `{source}`) now returns `{ok, results, crosscheck, warnings, max_error_in, rolled_back}`. It drops both cameras' old poses first (kept in memory for rollback; intrinsics are kept), solves both, and runs the pair check on the **new** pair (each solve is checked against the other camera's new pose, never the old one). If either camera fails, or the new pair's out-of-sample cross-check is over 2 in, **both old poses are restored** (`rolled_back: true`; on a first calibration nothing is left saved). `warnings` aggregates the per-camera `warnings` (prefixed `cam0: ...`) and the cross-check warning.
- **`POST /api/calib/extrinsics/{cam}`** and **`.../auto`**: a failed pair check against the other camera's pose answers **409** with a string field `hint` ("if both cameras moved, use Auto-calibrate all (or Recalibrate both)") and `pair_check_failed: true`, plus the usual numbers (`crosscheck_error_in`, `oos_error_in`, `reprojection_px`). Body `{"force_single": true}` skips only that pair check: the solve is saved and the other camera gets `pair_stale: true` until it is re-solved. Per-camera `.../auto` returns `warnings` (list of strings: HIVE-only accuracy, default lens, "no tag outside this solve is visible to this camera: the result is not independently checked", the `force_single` note), the same list `auto_all` aggregates.
- **Status.** `cameras[cam].pair_stale` (bool) and a warning `camera cam1: its pose was not checked against the other camera ...` while true; cleared when that camera is solved again, by `auto_all` success, or by reset.
- **`POST /api/calib/reset`** body `{"cam_id": "all" | "cam0"}` or `{"cameras": [...] | "all"}` (default all) → `{ok, reset: [cams that had a pose], cameras: [requested], kept: "intrinsics", rollback: {extrinsics: [{cam_id, rvec, tvec, rmse_in, ...}], solve_tags, clicks}}`. Deletes the extrinsics (poses), keeps the intrinsics and their sources; 404 for an unknown camera. `rollback` carries what was removed.
- **Lens quality.** `POST /api/calib/intrinsics/{cam}/stop` grades the checkerboard RMSE: over 2 px is saved with `intrinsics_source: "measured_poor"` (response `intrinsics_source`, `warning`), 1 to 2 px is `"measured"` with a `warning`, under 1 px has none. `measured_poor` keeps the status warning `camera X: the lens calibration is poor (RMSE n px): re-run the Lens step closer, 1.5-3 ft from the camera` permanently; `measured` at 1 to 2 px keeps a milder one. `intrinsics_source` of a camera is now one of `measured`, `measured_poor`, `profile`, `default`.
- **`POST /api/setup/finish`** returns `{ok: true, calibration_source, max_error_in, out_of_sample, oos_error_in_per_camera: {cam: n|null}, warnings: [...], warning?}` or 409 `{detail, reasons: [...], refused: true, ...numbers}`. It refuses for default lenses, a `measured_poor` lens (`intrinsics_poor_cameras`, reason "re-run the Lens step closer, 1.5-3 ft"), a `pair_stale` camera (`pair_stale_cameras`), a cross-check that cannot run or is over 1 in, or a camera whose own out-of-sample error is over 1 in. It never passes an in-sample check silently: for every camera without an independent check `warnings` has "camera cam0 cross-check is in-sample: tape errors, resolution mismatch or a camera swap would not be detected; verify by clicking the 8 corners". The match-start HIVE state is not consulted.
- **`POST /api/calib/crosscheck`** is documented above (body `{"in_sample": true}` optional; out-of-sample by default).
- **`POST /api/calib/hive_tags/learn`** with exactly one tag-reading camera (the other sees no HIVE tag) returns 200 `{single_camera: true, camera, learned: false, learned_ids: [], pnp_error_in: {id: inches}, up_cell_error_in, complete, reason, visible_per_camera, missing_ids}`: each visible tag's single-camera PnP position is compared with its computed (CAD) position; `complete` is true when the audience state is learned or this state is audience-up with `up_cell_error_in` under 1 in.
- **Packaged exe.** `--open-browser` is on by default when the app runs frozen (the exe); `--no-browser` turns it off everywhere. `--demo` still opens the browser.

## Done gate, joint cluster check, advice rules (v1.8, 2026-10-11)

- **`POST /api/setup/finish`** additionally returns 409 when `calibration_mismatch` is non-empty (a camera's frame size differs from its intrinsics; the body carries `calibration_mismatch: {cam: "1280x720 vs 1920x1080"}`) and when a camera is `pair_stale`, and adds to `warnings` (still 200) `camera cam0 was solved from only 2 tag(s) (100, 103): a third tag makes the pose much less sensitive to a mis-taped tag; ...` for every camera whose extrinsics came from fewer than 3 tags.
- **`POST /api/calib/hive_tags/learn`, single-camera path.** For every tag cluster seen (ids of one `(alliance, cell)` in `field_constants.APRILTAG_IDS`) the pose is estimated **jointly from all visible tags of the cluster** (one planar PnP over every corner, the cluster treated as a rigid body of the computed corners), mapped into the field with the camera's extrinsics and compared with the computed corners. The response adds `cluster_error_in: {"red_audience": inches, ...}`; `pnp_error_in[id]` is each tag's mean corner error from that joint estimate; `up_cell_error_in` is the cluster error of the learned state's up cell; `complete` is true only under 1 in (or when the audience state is already learned). On the test rig (kit + red HIVE read by one camera, 16 corners) the red audience cluster error is 0.42 in.
- **Advice** "Tip both HIVEs so both audience CELLs are up before calibrating (...)" in `GET /api/setup/status` `recommendations` now fires only when (a) any camera sees a blue audience tag upside down, (b) any camera sees the blue far cluster upright, or (c) a camera sees the red audience cluster upright but no blue audience tag although the computed blue audience tags lie inside its picture (by that camera's calibration; without one rule (c) does not fire). A camera that reads no stickers never triggers it.
